# Agregar conversaciones desde un export de WhatsApp

The user only hands over the export file. Everything else — which days are new, what's worth
keeping, how to write it, where it goes — is decided here. Don't ask questions the steps below
already answer; ask only if the file isn't a WhatsApp export or nothing in it is new.

Data lives in `src/data/whatsapp-conversations/`:

- `YYYY-MM.json` — one array per month of `{ "title", "date", "summary" }`, sorted by date.
  Entries summarized from an event (e.g. a virtual meetup transcript) also carry `"eventId"`:
  they show on that event's memorial page, link to it from `/conversaciones`, and don't count
  as the chat's last summarized day.
- `index.ts` — imports every month file (regenerated by the helper below).
- `members.ts` — community members as they're named in summaries. The page detects each
  conversation's participants by matching these names, and highlights conversations naming
  5+ members as _hilos grupales_. A name that isn't here is invisible to the UI.

Helper script (run from the repo root):

```bash
node .claude/skills/agregar-conversaciones/scripts/conversations.mjs <prepare|index|check>
```

## The export is private

The export is raw personal chat. Read it; never copy it into the repo, never `git add` it,
never publish it or paste long raw excerpts of it back to the user. Work on it only from its
original path and from the scratchpad directory.

## 1. Prepare the transcripts

If it's a `.zip`, unzip it into the scratchpad and use the `.txt` inside (`_chat.txt`).

```bash
node .claude/skills/agregar-conversaciones/scripts/conversations.mjs prepare <export.txt> <scratchpad>/conversaciones
```

This finds the last summarized day in the data and writes only newer messages as one compact
transcript per month (`<scratchpad>/conversaciones/YYYY-MM.txt`): `## YYYY-MM-DD` day headers,
`HH:MM Autor: texto` lines, media as `[imagen]`/`[audio]`/…, no system notices, phone numbers
replaced by `[teléfono]` and unsaved contacts as `[sin agendar]` or `~NombreDePerfil`.

It also prints the entries already written for the last summarized day. If the export shows
that day continued after those entries, rerun with `--since <that day>` and skip what is
already covered. If nothing is new, tell the user and stop.

## 2. Summarize, one month at a time

Months are large (100–450 KB). When there is more than one month, launch one subagent per
month file **in parallel** (general-purpose), giving each the absolute transcript path and the
whole of sections 3–5 below verbatim, and asking it to return only a JSON array of entries.
With a single small month, do it yourself. Then read every returned entry yourself before
writing anything: you own the result.

## 3. What to keep

Keep conversations someone would enjoy or learn from months later:

- technical debates and comparisons (tools, models, languages, architectures, practices),
- people explaining how they work, what they built or what they learned, with specifics,
- community life: events, talks, projects built together, memorable or funny moments,
- useful resources shared _with discussion_ around them.

Skip greetings, one-liners, lone links or memes with no discussion, scheduling/logistics,
off-topic politics or football, and anything section 5 rules out.

Density: roughly 1–2 entries per active day (recent months have 30–50 per month). One entry per
topic: merge a thread that continues across days into a single entry dated its first day, and
you may mention a related follow-up ("Al día siguiente, …", "Por la misma fecha, …").

## 4. How to write an entry

```json
{
  "title": "Charla sobre orquestación de agentes y SDD en un evento de agilidad universitario",
  "date": "2026-08-07",
  "summary": "Sebastián Soraire contó que presentó en un evento de agilidad de su facultad una versión ampliada de la charla sobre orquestación de agentes y SDD (spec-driven development: desarrollo guiado por especificaciones escritas antes del código) que se había dado en la comunidad semanas antes. Como el público mezclaba perfiles técnicos y no técnicos, evitó la jerga en las diapositivas. Compartió la presentación y el video del ejercicio que mostró en vivo, y contó que con ese mismo flujo armó en unas tres horas una herramienta simple de redirección de códigos QR."
}
```

- **Language:** Spanish, neutral rioplatense register, third person, past tense (the present
  is fine for habits: "usa", "prefiere"). No emojis, no quotes of whole messages.
- **title:** specific and descriptive, sentence case, no final period, usually 40–100
  characters. Name the concrete topic ("Combinar Fable, Grok y Composer según costo y
  velocidad"), not a vague label ("Charla sobre IA").
- **date:** `YYYY-MM-DD` of the day the conversation started.
- **summary:** one paragraph, usually 600–1200 characters. Who raised what, the positions
  people took, concrete facts (tools, versions, numbers, prices, results) and where it landed.
  Explain jargon or a lesser-known tool in parentheses the first time it appears, as in the
  example. Attribute opinions to the people who gave them; don't add your own.
- **Names:** refer to people by the full name they have in the export (saved contacts), e.g.
  "Facundo Padilla". Reuse the exact spelling already used in `members.ts` for known members.
  For `~Perfil` authors, use the profile name only if it is clearly a real full name;
  otherwise, and for `[sin agendar]`, write "un miembro de la comunidad". After the first
  mention in a summary, the first name alone is fine when unambiguous.

## 5. Privacy — never publish

The page is public. Leave out, or generalize so no one is identifiable:

- anything that could compromise someone professionally: job searches or being unhappy at
  work, salaries tied to a person or company, incidents with their clients or employer,
  internal company information,
- workarounds for platform restrictions, piracy, account sharing, anything unlawful,
- health, family, relationships, money trouble, religion or politics about a person,
- phone numbers, emails, addresses, private links (Drive, invite links), screenshots' contents
  that expose third parties,
- conflicts or heated arguments between members, and anyone who asked not to be quoted.

When in doubt, leave the conversation out and mention it in the final report instead.

## 6. Write the data

1. Append each month's entries to `src/data/whatsapp-conversations/YYYY-MM.json` (create the
   file as `[...]` if the month is new), keeping the whole array sorted by date. Never edit or
   reorder entries that were already there.
2. Register new months: `node .claude/skills/agregar-conversaciones/scripts/conversations.mjs index`
3. Update `members.ts` with every new person who takes part in a new entry (full name, in
   order of the list's rough frequency is fine; add spelling variants as `aliases` of the
   existing member instead of duplicating them). Don't add public figures who are only
   mentioned (authors, founders, streamers).
4. Validate, and fix until it passes with no unknown members left that are real members:
   ```bash
   node .claude/skills/agregar-conversaciones/scripts/conversations.mjs check
   pnpm exec prettier --write src/data/whatsapp-conversations
   pnpm exec tsc --noEmit -p .
   ```
5. If the dev server is running, open `/conversaciones` and check the new month renders, the
   histogram grew and the new group threads (5+ members) are highlighted.

## 7. Commit and report

Stage only `src/data/whatsapp-conversations/` (never the export) and commit with Conventional
Commits, following the repo's commit attribution rules:

```
feat(conversaciones): add <N> summaries from <mes inicio>–<mes fin> <año> chat export

Cover the WhatsApp group from <first day> to <last day>. <New month files / members added.>

<One line on anything left out for privacy, in general terms.>
```

Don't push. Report to the user: entries per month, new members added, how many new _hilos
grupales_, and the judgment calls (conversations skipped for privacy, ambiguous names) in
general terms without quoting private content.
